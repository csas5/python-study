代码重构
我的代码问题是成绩的输入和验证代码重复了。
为什么要抽函数？
因为函数许多内容重复以后增加新参数有许多修改的地方
不要重复自己---这是一个重要的思想
第一个重构：input_score()
我们希望把：
“让用户输入一个合法成绩”
单独变成一个函数。

他应该负责用户输入-转换float-判断0-100-合法-返回成绩-不合法-重新输入

注意：这个函数不应该知道 Student 是什么。

他只用负责一件事：获得一个合法成绩

这就是单一职责

一个函数尽量只负责一个明确的事情。
新的设计：
需要把“重复输入直到正确”放到函数里面

把不同职责拆成独立函数，可以降低代码重复，提高可维护性。

input_name()
→ 只做空值检查

input_age()
→ 字符串 → int + 范围检查

input_score()
→ 字符串 → float + 范围检查

Day16：让代码更像一个真正的小项目

一个非常实用的思想：
“函数不只是返回数据，也可以负责一整段流程”
也就是说可以把“添加学生这一整套流程”单独变成一个函数

今天的学习目标
函数的进一步拆分
student.add_student()
负责：
业务操作：把学生对象加入列表。

add_student_flow()
负责：
用户操作流程：让用户输入并完成一次添加。

现在的mian：
if choice == "1":
    一大堆代码

elif choice == "2":
    一些代码

elif choice == "3":
    一些代码

elif choice == "4":
    一些代码

以后可以逐渐变成：

if choice == "1":
    add_student_flow()

elif choice == "2":
    show_students_flow()

elif choice == "3":
    delete_student_flow()

elif choice == "4":
    update_score_flow()

这样main可以控制整个操作流程
第一个目标：

原来：
choice == "1"
    ↓
几十行添加学生代码

现在：
choice == "1"
    ↓
add_student_flow(students)

这就是把具体流程封装起来。

很重要的一点：

重构不是“函数越多越好”，而是“职责清晰且不过度拆分”。
复杂流程 → 值得抽函数
已经很简单 → 不必强行抽
